# 工具开发指南

本指南适用于人工开发与 AI 生成代码。根目录 `AGENTS.md` 是入口；新增工具前先阅读本文件。朱富贵火锅计算器为独立页面，保留自身布局、配色与结算交互，不套用公共工具的颜色和按钮规范。

## 一、目录与接入

- `src/config/tools.ts` 是首页、分类菜单、面包屑和工具路由的共同注册表。填写唯一名称、中文标题、描述、分类、路径、关键词和懒加载组件；不要在页面中另写一份导航数据。
- 一级分类在 `src/config/categories.ts` 中维护；分类不显示图标。普通工具沿用框架内的菜单和面包屑。只有确实独立的页面才使用 `standalone`。
- 多数新工具使用 `DevTool`，复用工具标题、描述、卡片、双列布局、表单及反馈样式；有特殊编辑器布局时使用 `ToolWrapper`。历史时间与编码工具由 `StandaloneTool.vue` 适配，这个文件名不表示它们脱离主框架。
- Vue 组件负责输入、执行状态和展示；纯计算放在 `src/utils`，复杂任务放在 `src/workers`。不要把转换算法、表格序列化和金额公式重复写在模板内。
- 使用 TypeScript 类型约束输入、输出和 Worker 消息，不用 `any` 绕过输入校验。

## 二、颜色与按钮

所有界面颜色集中在 `src/assets/theme.css`。默认蓝色，支持蓝、绿、紫三种主题；浅色在 `:root` 配置，深色在 `:root[data-theme-mode="dark"]` 内覆盖。修改 `--theme-blue`、`--theme-green`、`--theme-purple` 调整预设颜色，`--theme-accent` 引用所选预设，`--accent` 在深色模式自动提亮；次按钮、浅背景、边框、悬停和按下色由主色派生。主色变化后必须检查文字对比度。

顶部主题设置提供浅色、深色和跟随系统（默认）三种显示模式。`src/theme.ts` 在应用挂载前恢复设置，通过根元素属性应用全局主题并同步图标；显式模式不受系统变化影响。仅将颜色和显示模式保存在 `localStorage` 的 `vuebox.theme`，不保存工具输入。损坏或不可用的存储回退为默认设置；多个标签页同步偏好。组件不能自己读取存储或单独判断系统深色模式；独立朱富贵页面继续使用自身的系统配色。

| 变量 | 用途 |
| --- | --- |
| `--accent` / `--on-accent` | 主色、主色背景上的文字 |
| `--accent-hover` / `--accent-active` | 主操作悬停、按下 |
| `--accent-bg` / `--accent-border` | 选中区域、提示区域、焦点边框 |
| `--bg` / `--social-bg` / `--code-bg` | 页面、次级区域、代码区域 |
| `--text-h` / `--text` / `--border` | 主文字、说明文字、分隔边框 |
| `--button-bg` / `--button-hover` / `--button-active` | 次操作实心背景 |
| `--success` / `--error` / `--warning` / `--info` | 语义状态颜色 |
| `--json-*` / `--diff-*` | 语法类型及差异标记 |
| `--overlay` / `--shadow` | 遮罩与阴影 |
| `--checker-*` / `--marker-*` / `--image-base` | 图片透明网格、取色定位、对比度参考底板 |

Header 与标签页图标由 `src/theme.ts` 读取同一组颜色生成；没有独立的固定紫色 SVG。通过主题设置切换时即时更新；修改主题文件后重新加载页面验证图标，构建部署后也会自动使用新主题。

CSS 层顺序为 `base → components → controls`。入口必须先导入 `style.css`，再加载路由，保证样式层初始化顺序。组件的 `<style scoped>` 内容写在 `@layer components { ... }` 内，不在组件外定义全局颜色，也不使用 `!important` 绕过公共按钮。

```vue
<div class="controls">
  <button type="button" class="button-primary" @click="execute">开始转换</button>
  <button type="button" @click="clear">清空</button>
  <button type="button" :disabled="!result.output" @click="copy(result.output)">复制结果</button>
</div>

<style scoped>
@layer components {
  .result-section { margin-top: 20px; border: 1px solid var(--border); }
}
</style>
```

- 操作按钮统一使用实心背景。主操作用 `button-primary`，次操作不加颜色类；模式按钮通过 `aria-pressed` 和选中状态表达当前模式。历史 `primary`、`accent` 等类由公共样式兼容，新代码不要继续增加别名。
- 互斥模式切换复用 `SegmentedControl`，通过 `v-model`、中文 `label` 和 `options`（`value` / `label`）接入。控件采用单选按钮组语义与整体边框，支持方向键、Home / End 和 Tab 导航；只更新模式，不执行转换或计算。按钮外观统一由 `controls.css` 管理。
- 下载链接使用 `button-link`。普通导航链接仍保持链接语义。
- `data-button` 仅用于 JSON 树节点、差异行、取色色块等直接展示数据的控件，保留紧凑尺寸、语法色或像素色；不可用它规避主操作按钮规范。它们的底色仍使用全局实心表面。
- 颜色转换的用户输入、原始图片像素、示例 HEX 等属于业务数据，不应随主题变化。图片对比度计算的白底也不能误改为深色页面背景。
- 成功、错误、差异类型不能只靠颜色表达，需配合中文文本、类型或标签。

## 三、执行与结果状态

默认流程：输入 / 载入示例 → 点击执行 → 显示结果 → 复制 / 下载。首屏只展示输入默认值和结果占位，不自动计算。输入默认值不等于计算结果。

同步小任务可使用 `src/composables/useManualResult.ts`。它不会在初始化或输入变化时调用计算函数；输入、选项变更时同步清除旧结果。计算函数自行把已知输入错误转换成中文错误状态。

```ts
const { result, execute, reset } = useManualResult(
  [input, mode],
  () => {
    try { return { output: convert(input.value, mode.value), error: '' } }
    catch (error) { return { output: '', error: (error as Error).message } }
  },
  () => ({ output: '', error: '' }),
)
```

- 不在 `computed`、`watch`、`onMounted` 中自动生成转换或计算结果。`computed` 可以派生已提交结果的展示信息。
- `watch` 负责让旧结果失效，优先用 `flush: 'sync'`，避免同一操作中先修改输入再执行时结果被后续 watcher 清掉。
- 清空应清除输入、结果、错误和复制反馈；重置恢复默认输入并清除结果。生成器的“清空结果”可以保留生成选项，按钮文案需说明。
- 载入示例和导入文件不直接执行转换。Excel 选择文件时可读取工作表名称，再选择表及选项、点击转换；图片 Base64 选择文件后点击编码，解码也由按钮触发。
- 输入改变后旧结果不能继续复制、下载或用于比较；异步任务必须取消或忽略过期回调。
- 正在执行的操作显示中文进度，避免重复提交；失败显示中文原因及可执行的恢复方法，不把失败伪装成空成功结果。
- 表单使用 `@submit.prevent` 支持 Enter 提交，明确次操作 `type="button"`；多行文本中 Enter 应继续换行。

允许的实时交互：

- 世界时钟和“当前时间”提示持续刷新。
- HTTP 状态码、时钟目录、首页的搜索、分类和分页即时过滤。
- JSON 语法高亮和输入校验、Cron 可视化编辑和表达式校验即时更新；格式化输出、执行时间预览仍由点击生成。
- 图片取色属于直接操作：加载图片显示预览，鼠标悬停显示像素提示，点击或键盘移动选择颜色。
- 已有结果的显示格式（UUID 大小写、连字符、图片 Base64 展示格式、JSON 树形/代码视图）、密码显隐和已计算摘要的比较允许即时更新，不重新执行原始计算。

## 四、本地处理、资源与边界

- 用户文本、令牌、密码和文件只在浏览器处理，不发送到网络，不写日志，不默认保存到 localStorage、URL 或持久存储。
- 复制优先复用 `useLocalClipboard`；失败时提供手动选择复制提示。文件下载用 Blob URL，替换、清空、卸载时及时 `URL.revokeObjectURL`。
- 大文件、正则、SQL、差异计算、Excel 解析等使用 Worker。复用 `useWorkerTask` 的超时、终止和请求代次机制；输入变化、取消和卸载都应清理 Worker 与计时器。
- 非 Worker 异步处理（图片加载、文件读取、摘要计算）同样需要代次校验，旧任务不能覆盖新输入或清空后的页面。资源限制先检查再读取；错误与终止都清理回调。
- 使用 `onBeforeUnmount` 释放 interval、timeout、对象 URL 和监听器；不要给每张世界时钟卡片创建单独 interval。
- 设置明确的输入大小、批量数量、预览条数和运算时间上限，并在界面说明。预览截断不得悄悄截断复制或导出结果。
- 用户内容通过文本插值、textarea 或安全的结构化渲染展示，禁止直接 `v-html` 注入。HTML 看起来像代码时也必须作为数据保留。
- 空字符串与数值 0 分开处理；金额保留分币精度，大整数用 BigInt 或保留原始文本；不要为了统一样式改变既有计算口径。
- 时区使用 IANA 名称及 `Intl` 规则，按所选日期计算夏令时；固定偏移和城市时区不可混为一谈。

## 五、布局与可访问性

- 复用框架内容宽度；桌面多列、移动端单列，子项设置 `min-width: 0`，长文本换行，表格和代码在区域内滚动，避免整页横向溢出。
- 可见输入需要中文 label；图标或重复复制按钮需要明确 `aria-label`。模式开关使用 `aria-pressed`，展开控件使用 `aria-expanded`。
- 保留键盘焦点轮廓。错误用 `role="alert"`，执行及复制反馈用 `role="status"`，不要让每秒时钟成为持续播报的 live region。
- 自动滚动等动画遵循 `prefers-reduced-motion`。不要为了按钮统一破坏数据表的行高、JSON 虚拟列表高度或取色色块。

## 七、交付检查

1. 对计算逻辑、边界、错误和取消行为添加有意义的测试；`tests/toolConventions.test.ts` 防止界面硬编码颜色及自动执行回归。
2. 运行 `npm test`、`npm run build`，确保 TypeScript 和生产构建通过。构建通过不能代替界面检查。
3. 在浏览器检查初始无结果、示例仅填入、执行出结果、输入改变失效、错误、清空/重置、复制/下载，以及异步任务的取消或过期回调。
4. 检查浅色、深色、桌面和窄屏，主次按钮、导航选中态、数据高亮、长内容和键盘焦点。部署子路径使用 `import.meta.env.BASE_URL`，验证懒加载页面与 Worker 资源。
5. 文本使用 UTF-8，保留已有 BOM 状态，CRLF 行尾且文件末尾保留一个换行；最后依次运行 `npm run fix:eol`、`npm run check:eol`。不转换二进制文件，不擅自暂存或提交。
